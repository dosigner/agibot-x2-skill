# 배포와 UI에서 확인한 교훈

- 소스 변경, 테스트 통과, 서비스 적용, 브라우저 제공 파일, 실제 하드웨어 동작은 별개의 단계다. 2026-11-13에는 새 JS와 구 API가 동시에 관측된 기록이 있다.
- 운영 서버가 새 remote worker를 디스크에서 읽으면서 모듈 bundle은 구버전인 조합은 import 단계에서 실패할 수 있다. 서버/worker 계약을 함께 확인한다.
- 화면에 과거 지도/프리셋 실패/마지막 pose가 남아도 현재 상태일 필요는 없다. 원본 run/stamp/hash와 history 배지를 유지한다.
- 8908 coordination은 lock과 active task를 보지만, 미등록 채팅과 외부 프로세스는 놓칠 수 있다. chat 확인이 별도로 필요하다. 등록은 작업 종료 후 해제하며 분리한 background process까지 자동 추적된다고 가정하지 않는다.
- 자료를 읽는 UI도 대형 상태 복사와 여러 탭의 중복 polling으로 로봇 제어 사전 조회를 지연시킬 수 있다. 이전 측정과 같은 표본 수/부하에서 재현하고 전송/계산/렌더 시간을 나눈다.
- UI 취소 요청, PC2 입력 닫힘 응답, 원격 종료, 실제 정지는 서로 다르다. timeout을 성공적인 취소로 바꾸지 않는다.

이 패키지는 현재 dashboard를 배포하거나 재시작하지 않는다. 프로젝트의 실제 coordination 문서가 없으면 이 과거 요약으로 명령 경로를 추측하지 않는다.
