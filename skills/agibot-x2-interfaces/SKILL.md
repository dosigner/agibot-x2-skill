# AGIBOT X2 Ultra

## 요청과 필요한 자료

1. 설명, 기존 코드 변경, 새 구현, 자체 알고리즘 중 요청 의도를 정한다. 이미 결정된 조건을 유지한다. 막연한 요청에는 사용 상황과 입출력을 확인한다. 새 구현의 언어가 미정일 때만 C++/Python을 질문하고 기존 파일 언어는 유지한다.
2. [기능 목록](references/index.md)에서 필요한 ID를 고른다. 복합 요청은 여러 ID를 연결한다. Python 3.10 이상이면 이 파일이 있는 실제 스킬 폴더를 기준으로 `python3 <스킬 루트>/scripts/lookup.py --feature 4.1 --sensor rgbd --language python`을 실행한다. 작업 프로젝트와 스킬 루트를 구분한다.
3. 해당 기능 파일 또는 조회 결과의 **공식 문서 링크를 실제로 열어 필요한 절을 읽는다**. 이 공개판은 메시지 정의 원문, 엔드포인트 계약표, 관절·FOV 수치표를 포함하지 않는다. 링크를 찾은 사실만으로 필드·타입·경로·QoS·주기·단위를 확인했다고 하지 않는다.
4. `--search 'RGB-D'`, `--example 14 --sensor rgbd --language cpp`, `--type TouchState`는 관련 링크를 좁히는 도구다. 타입 조회도 정의 대신 출처 링크를 반환한다. 큰 링크 색인 전체를 로드하지 않는다.
5. 공식 사이트에 접근할 수 없으면 설치된 `.msg/.srv/.action`, 사용자가 제공한 문서·코드 등 확인 가능한 근거를 사용한다. 그것도 없으면 구체적인 계약을 미확인으로 남기고 자료를 요청하며 가능한 설명·코드 구조 변경·순수 로직 테스트를 계속한다. 기억으로 필드나 제한값을 채우지 않는다.

링크는 AimDK_X2 문서에서 수집한 탐색 경로다. `en/latest`는 바뀔 수 있다. 문서 버전과 실제 SDK·펌웨어 버전을 대조한다. 예제는 해당 언어의 초기화·콜백·종료 경로까지 검토한다. 링크 존재와 예제 실행 검증을 구분한다. ROS 2 정의 형식을 사용하며 `aimdk_msgs` 같은 제조사 타입도 허용한다.

## 결과 만들기

학습 전에는 [요청별 완료 조건](references/workflows.md)의 학습 절을 읽고 개념 → 인터페이스 → 데이터 흐름을 설명한다. Mermaid 또는 텍스트 흐름도를 붙인다. 현재 문서를 확인하지 못했다면 일반 ROS 설명과 X2의 확인된 계약을 구분한다.

파일 변경은 기존 구조를 읽고 실제로 수행한다. 자체 알고리즘은 입력·출력·시간·좌표계·가정·실패 조건을 설계한 뒤 구현한다. 제조사 예제를 사용자 알고리즘 개발의 결과물로 대신하지 않는다. 필요한 언어 적용 기준은 [C++·Python](references/language-patterns.md)에 있다.

관절 목표·IK·자세·궤적·제한 검사 전에는 [관절 기준](references/robot/joints.md)을 읽고 공식 범위를 조회한다. 기체는 **X2 Ultra Edition**이며 다른 판의 값을 섞지 않는다. N/A, 좌우 관절과 배열 순서를 추측하지 않는다. 센서 시야·투영·융합·거리 계산은 [센서 기준](references/robot/fov.md)에서 공식 자료와 실제 보정의 대조 절차를 따른다.

## 실행과 보고

빌드·실행 전에는 [환경과 검증](references/environment-and-validation.md)을 읽는다. 모션 없는 센서 구독·상태·진단 조회는 허용된다. 초기화·콜백·launch 전체를 확인한 뒤 제한 시간과 종료 조건을 둔다. 모션 명령 발행, 모션 서비스·Action 호출, 제어 활성화·관련 모드 전환은 실행하지 않는다. 예제 이름이 조회라고 해도 실제 호출을 확인한다.

최종 답변에는 요청 결과와 출처, 실제 수행한 검사와 미실시 검사를 구분한다. 네트워크 부재는 설치 실패와 다르지만 원문 계약 확인을 제한한다. 파일 설치·오프라인 링크 조회·실제 클라이언트 발견·로봇 검증을 구분한다. 이 스킬은 물리 인터록이 아니다.
