# 지도와 시간에서 얻은 교훈

- **2026-10-20 내장 nav:** 패키지/요청 정의 존재와 no_nav 실행 profile이 함께 관측됐다. 설치 유무, RPC listen, 실제 mapper/pose 수신, 목표 실행을 분리해야 한다. 당시 기동 스크립트의 임의 고정 TF는 실기 좌표 보정의 근거가 아니다.
- **2026-10-26 deskew:** 첫 점 중복 보정과 경계시각 미처리 결함을 수정한 기록이 있다. 고정 source와 binary hash를 확인하고 합성 경계 시험 및 같은 입력 replay를 유지한다.
- **2026-11-05 IMU 지연:** 한 실행의 7개 간격 이상에서 지연 대부분은 host packet 관측→libc read 복귀 전 범위에 있었다. 스케줄 대기, 소켓/커널 전달, 계측 overhead를 하나의 원인으로 확정할 수 없었다. 다른 실행의 queue 표본을 같은 사건의 증거로 합치지 않는다.
- **2026-11-16 FAST-LIO:** 긴 계산과 LiDAR callback이 같은 callback group에서 직렬 실행되는 병목을 계측했다. 약 10 Hz raw를 검증하고 격번 공급한 최종 90 s 시험에서 발행/callback 409/409, 최대 관측 지연 0.216 s였다. CPU 부하와 입력이 고정되지 않은 비교이므로 모든 장면의 최적값이나 무손실 보장으로 쓰지 않는다.
- 같은 날 일반 경로에서 역행 stamp와 평소보다 넓은 point time 범위의 입력이 거부됐다. 재시험 성공은 해당 이상 메시지의 생성 원인 해결이 아니다.
- **2026-11-09 재위치:** 저장 지도 정합과 모델 기반 높이로 tracking을 관측했지만 바닥/센서 원점 실측은 없었다. ICP inlier RMSE 약 3 cm는 실제 위치 오차 3 cm가 아니다. 독립 FK와의 수치 일치는 물리 보정 검증이 아니다.
- **2026-11-17 자체 nav:** map/IMU/base 변환, raw scan 기반 최신 통행 공간과 PC2 follower가 필요한 실행 경계로 정리됐다. 내장 no_nav는 자체 nav의 blocker가 아니다.

저장 지도는 run별 원점과 hash가 핵심이다. 미리보기 점수 제한, PLY 전체 제한, planner 입력 제한은 다른 계약이므로 현재 코드에서 각각 확인한다. 화면 축소점을 원본으로 export하거나 planner가 제한 초과 원본을 조용히 잘라 쓰지 않게 한다.
