# 실행 진단에서 확인한 교훈

아래는 날짜가 있는 특정 X2 설치의 기록이다. 현재 장치 보장은 아니며, 경로가 없으면 동등한 현재 설치 근거를 찾는다.

| 관측/구현 근거 | 재사용할 판단 | 다시 확인할 조건 |
|---|---|---|
| 2026-10-19 SDK prebuilt 폴더에는 msg가 있었지만 Python 생성 모듈이 빠져 import 실패. firmware common prefix 적용 뒤 수신됨 | 타입 정의 파일과 실행 가능한 타입 지원을 따로 확인 | Python ABI, overlay 순서, 펌웨어 변경 |
| 같은 날 180개 토픽 발견, 선택한 40개 중 33개 수신 | 그래프 존재, publisher 존재, 실제 수신을 별도 결과로 기록 | 짧은 무수신을 기능 부재로 해석하지 않음 |
| PC2 내부 수신은 성공해도 DDS 프로필은 보드 인터페이스에 묶임 | SSH 터미널로 결과를 받은 것은 Mac의 DDS 구독 성공이 아님 | 네트워크 전환, 인터페이스 변경 |
| 2026-10-26 첫 GET timeout 뒤 같은 클라이언트의 GET 성공 사례 | discovery readiness와 응답 readiness를 분리, 요청별 식별과 대기 시간 기록 | 패킷 손실이 원인이라는 결론은 양단 추적 필요 |
| 2026-11-09 이후 유선/Wi-Fi 전환 기록 | 제어 소켓 목적지, host route, 보드 신원을 함께 확인 | 연결 실패를 전원 꺼짐/옵션 미설치로 단정하지 않음 |

수신률은 N≥2이고 경과가 양수일 때 `(N-1)/(t_last-t_first)` [Hz]로 계산한다. 같은 단조 시계를 사용하고 관측창과 공백도 남긴다. 이는 설정 주파수나 무손실 성능이 아니다.

타입 import, 구독, 서비스 호출, launch를 같은 단계로 취급하지 않는다. 구독 프로그램도 callback 부하를 만들므로 검사 그룹과 시간을 제한한다.
