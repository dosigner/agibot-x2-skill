# 음성에서 재사용할 실패 지식

- **2026-11-13:** wake match, lease 승인, Live 연결이 있었지만 turns=0, PCM chunks=0으로 idle 종료된 시도가 있다. 이 결과에서 스피커나 볼륨을 원인으로 확정할 수 없다. 최초 입력 PCM 전송과 공급자 발화 종료 이벤트가 다음 관측 지점이다.
- **2026-11-09:** processed 침묵 시 raw fallback의 대기보다 발화 종료 무음 판정이 빨라 약 0.352 s 합성 발화를 버리는 반례를 재현했다. 발화 버퍼를 전환 판단까지 유지하는 회귀 검사를 남긴다. 이 재현이 당시 실기 무응답의 직접 원인이라는 증거는 별도다.
- 제조사 processed publisher가 존재해도 패킷 0일 수 있다. 첫 턴이 raw라면 processed 무수신을 첫 턴 원인으로 연결하지 않는다.
- ROS packet 수신, synthetic PCM cloud 응답, HAL publish, 사람의 실제 대화는 서로 다른 검증이다. 5분 서비스 생존이나 synthetic 양성/음성 분류 소수 건으로 사람 호출어 인식률을 주장하지 않는다.
- Moonshine/Whisper/KWS/APM 후보는 실행 설정, 모델 hash, 설치 dependency와 실제 선택 여부로 구분한다. 저장소에 후보 코드가 있다는 사실은 PC2 배포가 아니다. 호출어 모델 변경은 음향 입력 품질과 대화 routing 결함을 자동 해결하지 않는다.
- 다중 마이크 AEC/beamforming은 참조 지연과 마이크 위상 정렬을 검증해야 한다. 합성 echo 감쇠 dB를 실제 방/스피커에서의 감쇠로 보고하지 않는다.
- PC3 HAL 복구와 PC2 Canis 소스 변경은 별도 조치다. 어느 보드를 재시작했는지, 수신/전사/출력 중 어느 단계가 달라졌는지 남긴다.
