# 얼굴 출력에서 확인한 사항

- 800×480에 16:9 영상을 비율 유지로 맞추면 800×450이므로 상하 각 15 px 여백이 생긴다. 이는 기하 계산이며 player fit 구현 검증은 아니다.
- 프로젝트의 60 fps H.264/yuv420p 콘텐츠 제작 설정은 패널 60 Hz 측정이 아니다. `ffprobe`로 실제 출력 파일을 검사한다.
- PC2의 이벤트 처리와 PC3의 렌더러는 별개다. 파일 전달 후 PC3 read 권한과 hash를 확인한다.
- 2026-10-20 터치 출력에서 제조사 화면 우선순위가 사용자 반응보다 높아 보류된 사례가 있다. 이후 명시적으로 승인된 입력 분리로 해결했다. 이 과거 승인을 다른 장치/세션의 설정 변경 권한으로 재사용하지 않는다.
- mode=1 종료 뒤 제조사 기본 화면이 끼어든 사례와 mode=2+직접 중립 복귀의 관측이 있다. 모드 숫자를 모든 player에 공통인 API 계약으로 일반화하지 않는다.
- LED는 요청 수락과 상태 readback이 있었어도 약 1초 뒤 제조사 상태 표시로 덮였고 현장 사용자는 원래 색만 관찰했다. 화면/LED 요청 수락을 지속 표시 성공으로 보고하지 않는다.

보드별 현재 endpoint와 mode 계약은 설치 서비스에서 다시 읽는다. 공개 패키지에는 제조사 endpoint 전체 표나 영상 자산을 복제하지 않는다.
