# X2 PC3 얼굴과 표정

## 출력 계약

PC3 (`soc_index=2`)의 DRM mode와 실제 player의 dimensions/orientation을 함께 확인한다. [관측과 출력 충돌](references/lessons.md)을 읽는다. 2026-10-19 연결 기체의 DRM은 480×800, flutter-pi 콘텐츠는 landscape_right의 **800×480 px**였다. 이는 5:3 화면이며 패널 주사율이나 물리 크기 측정값은 아니다.

1. 원본 콘텐츠와 배포 사본의 hash를 보존한다. 로봇용 해상도, codec/pixel format, duration, audio 유무를 ffprobe 등으로 확인한다. 공유용 16:9 미리보기와 로봇 파일을 구분한다.
2. 요청 전에 현재 화면 소유자와 우선순위를 읽는다. 얼굴을 바꾸는 API는 GET 형태여도 상태 변경이다. 진단 조회와 재생 명령을 메서드 이름만으로 분류하지 않는다.
3. API 수락, 현재 경로 readback, 실제 디코딩/화면 출력, 현장 관찰을 분리한다. 파일이 PC2에 있다는 사실로 PC3 player가 읽을 수 있다고 판단하지 않는다.
4. 반응 후 중립 복귀는 실제 player mode를 확인해 설계한다. 이 프로젝트에서는 자동 기본 화면 복귀가 제조사 표정을 잠깐 끼워 넣는 사례 때문에 mode=2와 타이머 기반 명시적 중립 전환을 사용했다. 다른 펌웨어에서는 mode 의미부터 다시 확인한다.
5. 다른 높은 우선순위의 소유자에게 양보하고 필요하면 충돌하는 입력의 역할 분리를 검토한다. 우선순위 상승이나 반복 요청으로 화면을 빼앗는 해결책을 기본으로 쓰지 않는다.

## 검증

전체 프레임에서 눈/점의 clipping과 fit을 검사한다. 요청 중첩, 취소, 종료, 터치 중 대화, 오래된 이벤트와 중립 복귀를 시험한다. `enabled`, 프로세스 재시작 성공과 실제 부팅 후 복구는 별도다. 변경 범위가 콘텐츠뿐이면 제조사 agent 설정과 모션 서비스는 변경 대상이 아니다.

근거의 날짜, 출처 및 재확인 조건은 [근거 목록](references/evidence.md)을 따른다. 과거 보고서의 확인과 이번 실행의 확인을 분리해서 보고한다.
